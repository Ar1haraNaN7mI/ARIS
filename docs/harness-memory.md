# Harness 优化记忆

ARIS 在同一 ARIS_HOME 的不同任务间保存优化经验。每条评测关联一个稳定的问题编号，记下变更、选择依据、预测、观测、模型或评测条件，以及与上轮记录的关系。模型权重保持冻结。这一设计参考了 CRSI 的跨模型、跨评测续跑和 SIM 的变更记忆。[原论文](https://arxiv.org/abs/2611.18856)

## 日常执行

- `admin.dispatch.native.v1` 比较「每个角色写一份紧凑契约」与「引用共享输入，只写个别验收条件」两种已实现的控制提示。新模型可以使用同一建队协议的历史数据。相同模型的证据权重更高。只有已验证并实际提交的建队调用计为成功。输出截断、完整调用校验失败分别记录。同一尝试重复上报只产生一条记录。
- `team.cowork.start.v1` 记录带邀请 ID 的新执行开始。毫秒数从消息创建到真实的 `agent_started`，包含等待执行槽和文件的时间。评估空闲唤醒时，应同时核对邀请发出时对方的状态、文件占用和执行槽。若角色尚未开始主任务，独立的协作回合可以先处理来信，原任务继续遵守依赖。通知、已经运行的收件人不会凭空产生第二次开工。

## 已复核的派工故障

| 留存证据 | 根因与处理 |
| --- | --- |
| 上轮 KEI 获客任务，首次 `create_sub_agents` 调用收到 1,911 个字符、3,623 个 UTF-8 字节，最后一个字符串尚未闭合 | 控制层拿到的角色列表不完整。上次没有原始网关流或 token 计量，无法判定上游哪个环节丢失尾部。派工规则现在引用共享输入、复用角色首份任务，只对明确截断的整份清单进行一次有界重发。 |
| 更早的一次复杂审查，旧控制层触发 64 KiB 上限 | 旧计量将推理内容和分块里重复的调用标识计入控制参数长度。现版移除了这项上限，按调用索引拼回完整参数。回归包含八角色清单、重复标识和超过 256 KiB 的中文派工。 |
| 另一次较早的建队请求，网关在 schema 校验时返回 HTTP 400，并指明 `uniqueItems` | 工具定义使用网关支持的字段，角色、文件与依赖的唯一性由 ARIS 本地校验。该类协议错误与 JSON 中途结束分开处理。 |

同一份上轮获客任务可确认首次派工失败一次，随后同会话成功。以上案例来自不同运行。

## 长任务和交付材料

ARIS 按原文保存任务、角色说明、派工参数和协作回执。管理员发给每个角色的清单可以引用共享目标和材料路径。评审较长文档时，ARIS 将需要分批传送的正文存成工作区中的不可变 JSONL。索引写明路径、总字节数、页数和 SHA-256。普通对话与团队泳道均可用原生 `read_file` 从第 1 行起逐页读取，按顺序连接各页的 `text` 可还原原文。读取页本身会直接送入当前模型回合。

模型和上游接口各自有上下文窗口和单次输出 token 预算。若网关把创建调用标成未完成，或角色清单在 JSON 值内中断，原会话保留失败回执，并在同一时限内重新生成一次完整清单。ARIS 验证清单后才创建角色。网络故障和网关 schema 拒绝单独记录，便于定位对应的传输或协议问题。

团队收尾时会检查本轮主笔的最终交付快照。例如，主笔开始写稿后邀请来源角色核实一句宣传主张，来源角色的新回合可能晚于主笔最初读取的证据版本。等参与本轮的角色及稿件来源全部完成，如果来源版本、文件内容或有实质内容的协作记录使快照标为过时（`stale`），调度器会在原主笔泳道追加一次终稿复核（`final_review`）。主笔读取最新证据和上一版稿件，修订有变化的内容，并保留准确的原文。每次外部发起的执行最多追加一次，沿用本轮并发、回合数和时限预算。若复核中证据再次变化，ARIS 保留上次交付，标明原因并结束本轮。「已采纳」等单向通知只更新双方的聊天记录，查看交付页面也不会触发复核。

## 新问题的实验循环

通过 ARIS 本地控制接口调用下列方法。优化器读取同一问题的历史，包括失败的实验，并结合新环境提出候选修改、选择理由和可复做的验证。开发者或评测程序运行拟议修改，回传观测后再发起下一轮。日常派工只选择已内置的控制策略。

| 方法 | 用途 |
| --- | --- |
| `memory/experiments/evaluate` | 导入一次已有测量。提供 `evaluation_id`、`problem`、`edit`、`rationale`、`prediction`、`context`、`observation`、`passed` 和可选 `measurement_ms`。返回的分组以 `external.` 开头。 |
| `memory/experiments/propose` | 提供完整 `problem`、`context` 和 `objective`。一次 KEI 优化器调用返回保存在本地的提案 ID、所选修改、另一候选、选择依据、预测与评测方法。 |
| `memory/experiments/grade` | 提供提案 `id`、`passed`、`observation` 和可选 `measurement_ms`。实际观测与事前预测分别存储。用同一 ID 重试时，已记录的结果保持一致。 |
| `memory/experiments/recall` | 用完整 `problem` 读取符合当前记忆设置的评测记录。 |
| `memory/list`、`memory/delete`、`memory/clear` | 管理本机记录。删除单条使用 `kind=experiment` 与对应 ID。 |

例如把模型或评测集写入 `context`，将开工延迟的上限写进 `prediction`，测量后将耗时和收件人是否空闲填入 `observation`。续跑时保持问题编号一致，切换 `context`。同一日志保留最近 256 条评测和 256 个提案。记忆生成与检索沿用 ARIS 的两个独立设置。普通任务智能体接收的业务上下文与优化器实验历史分开存储和使用。
